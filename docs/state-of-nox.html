What it is

An issue tracker for one team of about twenty people. Projects, workflows that actually refuse a transition, boards whose columns are containers of statuses, releases that span projects, automations, and a GitHub App that does the half of the work nobody should be clicking.

None of it was reasoned from taste. We measured what Jira was doing for us and found that Utility Points was five different custom field ids, that the field recording who tested something kept no history at all, and that half the status changes on the board were already automation. Every decision below traces to one of those.

It runs today, on the office network, with four projects and a workflow captured from our real Jira. What it does not have is anyone in it.

Where every part of it actually stands

Three grades, and the middle one is the interesting one. Solid means built, checked, and it would survive somebody leaning on it. Thin means it exists and nothing has ever tested whether it is any good. Missing means it is not there and we know it.

Solid

11 Built, verified, and safe to lean on
Boards and workflow A column is a container of statuses, not a status — so two can share a column, and a status in no column stays off the board. Transitions refuse, and name what is available.
Issues and the event log Append-only: every field change is a row, 855 of them so far. This is the thing Jira could not do, and most of what is worth knowing reads history rather than current state.
Git A GitHub App — one authorisation by an org owner, no tokens pasted anywhere. Pull requests, branches, builds through the Checks API, and branch-name linking. 58 refs attached to issues — and, since this morning, the first three builds it has ever seen that were not seeded: its own CI.
Accounts and permissions Register, an admin approves, an admin grants project access. Argon2id, rate-limited, sessions in the database. A restricted issue answers “no issue CD-3” rather than “forbidden” — the second answer is itself information.
The admin audit Who changed a role, a status, or who can see a project — with the before as well as the after, because “changed a role” is not an answer and “member to admin” is.
The text editor Type ## and it becomes a heading; paste Markdown and it just works. It renders to elements rather than HTML, so nothing anybody writes can become markup — and a round-trip check runs on every build.
Labels Created by using them, not by an admin, and folded on the way in — so Flaky and flaky are one label rather than two.
Saved views A whole arrangement — the filters and the layout. Yours unless you share it.
Search Summary, description and comments. The comments are what make it work: half of what anybody remembers about an issue was said underneath it, not in its title.
It works on a phone From 320px up. The navigation becomes a sheet, the filters go to two columns, the issue view becomes a full-screen sheet. The list layout is the one that suits a phone and it is two taps away.
The gates run themselves GitHub Actions, on every push: the build, the round-trip check, the design-system audit, the dead-CSS report, and 39 tests against a real Postgres. Green in 46 seconds. Until this morning they only passed because somebody remembered to run them.

Thin

7 Built, and nothing has ever tested whether it is good
Asks and notifications Four kinds — confirm, explain, discuss, present — plus a bell, a count in the tab title and a redrawn favicon. All six asks in there are seeded.
Better looks like: it reaches you when Nox is not open. Real push needs HTTPS, which needs a deployment; Discord is the answer in the meantime, and was always the plan for after it is live.
Insights Flow, waiting time, and how much of the movement is automation. The charts are right; 66 issues is not enough for a median to mean anything, and the ratio it reports is a ratio of seeded data.
Better looks like: nothing to build. A month of real work in it, and then read the numbers.
Automations The engine is real — blocks, a job queue, a worker, an audit trail, 31 runs. But all five rules came from the seed, and nobody has ever written one.
Better looks like: somebody who is not the person who built it writes a rule without asking for help. If that is hard, the editor is the thing to fix.
Releases Cross-project and first-class, with artifacts that ship independently and a state machine that follows them both ways. Fourteen of them. The timeline is dense at fourteen and there is no phone-shaped version of it.
Better looks like: one real release run end to end — planned, shipped, and the dates disagreeing — before deciding whether the timeline needs anything.
My work and the team queue The screens most people would live in. They order work by three levers — the product owner’s, the lead’s and the developer’s — and no actual product owner or lead has ever pulled one.
Better looks like: a lead reorders their team’s week in it and the result is what they meant.
Tables on a phone They scroll sideways rather than becoming a list of cards. Honest and consistent — nothing is hidden any more — but nobody would call it good.
Better looks like: the accounts and views tables become cards under 600px. A day of work, and only worth it if anybody administers Nox from a phone.
All of the data Nineteen accounts exist. One human has ever signed in. Every issue, comment, ask and release you can see was written by a seed script.
Better looks like: the section below. This is the one that unlocks the other six.

Missing

3 Not there, and we know it
No deployment No domain, no certificate. Deliberate so far — a PoC that nobody uses does not need infrastructure — but it is now the thing blocking real notifications, because the browser will not do push without a secure origin.
Backups are not scheduled The flow exists and has actually been restored end to end, with a marker in the data to prove it replaced rather than quietly did nothing. Nothing runs it on a timer.
The field audit Which custom fields does anyone actually fill in? We have the machinery and have not run it. The same sweep for statuses and workflows is already done — that is where the captured workflow came from.

The decisions the rest hangs off

Five of ten. The others, with their reasoning, are in the repository’s own documentation.

History is first-class

Almost everything worth knowing reads history rather than current state, so every write goes through an append-only log. The whole data model hangs off this one.

One database, and it is Postgres

Accounts lived in a separate SQLite file until this month. Twenty-six columns held a user id and not one could declare a foreign key, because you cannot declare one across two engines — so deleting an account silently orphaned everything it owned. There are twenty-seven now.

Permissions live in the query builder

They were written correctly on four screens and wrongly on two, and nothing could tell the difference. A plain member could read a project they had been kept out of by asking for a colleague’s queue. It is one filter now, and three regression tests that were proved to fail against the old code.

The design system is a script

Material 3 is not a preference somebody remembers. Radius, elevation, motion, type, colour, hit area and undefined tokens are checked mechanically, and the check exits non-zero. It once passed for the wrong reason and had to be re-proved against five deliberate violations.

Git drives the tracker

Not the other way round, and not a two-way sync with Jira — that would make Nox a second place to look, which is the problem we started with.
